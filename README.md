# Ассистент по энциклопедии WikiBrand

RAG-ассистент по базе [wiki-brand.com](https://wiki-brand.com): отвечает на вопросы о брендах («как отличить подделку Boya», «какие бренды похожи на Benro») только по статьям энциклопедии и даёт ссылки на них.

**Стек:** Python 3.12, fastembed (ONNX), numpy, SQLite FTS5, DeepSeek, pytest.

**Статус:** шаги 1–3 из 5 — поиск, ответы с источниками, evals поиска и ответов. Дальше — FastAPI, Langfuse, Docker и деплой.

## Запуск

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # Linux/macOS: .venv/bin/pip

# Данные — репозиторий WikiBrand рядом с этим (или путь в WIKIBRAND_DIR)
python -m assistant.index                       # ~10 минут на CPU
python -m assistant.search "как отличить подделку boya"
python -m assistant.answer "какие бренды похожи на Benro"   # нужен DEEPSEEK_API_KEY
python -m pytest
```

## Как устроено

```
brands/ru/*/*/data.json ─→ куски по разделам ─→ эмбеддинги ─→ embeddings.npy
                                     └────────→ основы слов ─→ SQLite FTS5
Вопрос ─→ векторный поиск (30) ─┐
       └→ поиск по словам (30) ─┴→ Reciprocal Rank Fusion ─→ 5 лучших кусков
```

### Нарезка: куски по разделам статьи

Статья бренда в WikiBrand уже разделена по смыслу: история, продукция, технологии, где купить, аналоги, как отличить подделку, отзывы, FAQ, интересный факт. Кусок — это раздел; раздел длиннее 1 200 символов режется по абзацам или пунктам списка, пункт посередине не разрывается. Итого 13 824 куска на 1 255 брендов, в среднем 754 символа.

Каждый кусок начинается с заголовка:

```
Boya (боя) — Как отличить подделку: подделки, как отличить оригинал, как не купить фейк
```

- **Бренд** — без него кусок «Проверьте гравировку на крышке» не связан ни с каким брендом.
- **Транслитерация** — пользователи пишут «боя», «хонгдиан», а в статье Boya, Hongdian.
- **Какие вопросы закрывает раздел** — словами пользователя.

Ссылка у куска ведёт на страницу раздела, если она есть (`/poddelka`, `/istoriya`), иначе — на главную бренда.

### Эмбеддинги: fastembed и маленькая модель

`paraphrase-multilingual-MiniLM-L12-v2`: 384 измерения, 0,22 ГБ, понимает русский, работает на CPU через ONNX без PyTorch. У DeepSeek нет API эмбеддингов; модели крупнее (mpnet — 1 ГБ, e5-large — 2,2 ГБ) не помещаются на сервер с 1 ГБ памяти.

### Векторная база: numpy, а не Qdrant

13 824 вектора × 384 = 21 МБ. Точный перебор всех векторов — одно матричное умножение, миллисекунды. Отдельная векторная база окупается на миллионах векторов; здесь она добавила бы сервер, память и точку отказа без выигрыша.

### Гибридный поиск

Векторный поиск находит по смыслу («как распознать фейк» ≈ «как отличить подделку»), но плохо — по названиям и артикулам. Поиск по словам — наоборот. Каждый даёт 30 кандидатов, результаты объединяются через **Reciprocal Rank Fusion**: оценка куска — сумма `1 / (60 + место)` по обоим спискам. Складываются места, а не сами оценки: у косинусной близости и BM25 разные шкалы.

FTS5 в SQLite не знает русской морфологии, поэтому в полнотекстовый индекс кладутся основы слов (стемминг Snowball): «подделка», «подделку», «подделки» → одна основа.

## Оценка поиска

[evals/retrieval_set.json](evals/retrieval_set.json) — 81 вопрос: по 9 случайных кусков из каждого раздела, к каждому DeepSeek написал вопрос пользователя своими словами ([генератор](evals/make_retrieval_set.py)). Попадание — если в выдаче есть кусок того же бренда и раздела.

```bash
python -m evals.retrieval
```

| Режим | hit@1 | hit@5 | MRR | бренд@5 |
| --- | --- | --- | --- | --- |
| Поиск по словам | 0,31 | 0,74 | 0,48 | 0,96 |
| Векторный | 0,41 | 0,68 | 0,52 | 0,93 |
| Гибридный | 0,46 | 0,80 | 0,60 | 0,98 |
| **Гибридный + заголовки с темами и транслитерацией** | **0,53** | **0,93** | **0,69** | **1,00** |

hit@k — нужный раздел в первых k; MRR — среднее 1/место нужного раздела; бренд@5 — в первых пяти есть что-то о нужном бренде.

**Что показали промахи и что изменено:**

| Промах | Пример | Исправление |
| --- | --- | --- |
| Бренд найден, раздел не тот — 11 из 16 промахов | «какие бренды похожи на Benro» → «Отзывы» и «История» Benro, где конкуренты тоже упоминаются | В заголовок куска — какие вопросы закрывает раздел |
| Бренд кириллицей | «микрофон боя», «ручки хонгдиан» → чужие бренды | В заголовок — транслитерация названия |

**Ограничения оценки:** вопросы сгенерированы моделью по тексту куска и могут быть «удобнее» настоящих; часть эталонов спорная (вопрос «почему Infitary продаёт только онлайн» отнесён к «Истории», хотя отвечает и «Где купить»). Следующий шаг — набор вопросов, написанных вручную, включая бренды, которых нет в базе.

## Распознавание брендов в вопросе

Общие слова уводят поиск к чужим брендам: в «как отличить подделку **микрофона** boya» слово «микрофон» поднимало куски Synco и Sennheiser выше раздела о подделках Boya. Поэтому бренды из вопроса распознаются ([assistant/brands.py](assistant/brands.py)) и их куски дают третий список для RRF — не фильтр: в «Seiko или Orient» Orient может не быть в базе.

- **Как ищется название:** целым словом, латиницей и в транслитерации — «бенро», «хонгдиан».
- **Нечёткое сравнение** для написания на слух: «саундкор» ≈ «соундкоре», «ксяоми» ≈ «ксиаоми». Сначала давало 4 ложных срабатывания на 81 вопрос («просто» → Prostormer, «наушниках» → Nautica). Решение — частотная проверка: обычные слова встречаются в базе часто, искажённые названия брендов — почти никогда. Нечёткое сравнение — только для слов, которые есть не больше чем в 5 кусках. Ложных срабатываний — 0 из 81.
- **Место для каждого бренда:** в сравнении двух брендов лучший кусок каждого обязательно попадает в выдачу.
- **Модель знает, о каких брендах из вопроса статьи есть** — и не говорит «нет статьи» о бренде, который в базе есть.

## Ответы

[assistant/answer.py](assistant/answer.py). DeepSeek получает 5 найденных фрагментов с номерами и отвечает только по ним, ставя номера `[1]`, `[2]`. Ссылки на страницы собирает код по номерам — модель не может выдумать адрес.

Правила промпта: только факты из фрагментов; бренда нет в базе — «В энциклопедии WikiBrand нет статьи о …» без дальнейших подробностей; ответа нет в статье — «в статье об этом не сказано»; если энциклопедия говорит, что информации мало, — передать это, а не додумывать.

## Оценка ответов

[evals/answer_set.json](evals/answer_set.json) — 24 вопроса, написанных вручную, трёх типов:

- **ответ есть** (16) — среди источников ответа должен быть нужный бренд; в том числе бренды кириллицей («саундкор», «сеннхайзер», «хуавей») и сравнения двух брендов;
- **бренда нет в базе** (5: Casio, Rolex, Nike, Sony, Bosch) — ассистент должен сказать, что статьи нет;
- **ответа нет в статье** (3: цена конкретной модели, телефон поддержки, будущие релизы) — ассистент должен так и сказать.

Для каждого ответа судья (DeepSeek, температура 0) ищет утверждения, которые не подтверждаются фрагментами, на которые ответ ссылается.

```bash
python -m evals.answers hybrid hybrid+brand
```

| Поиск | Пройдено | Нужный бренд в источниках | «Статьи нет» | «В статье не сказано» | Без неподтверждённых утверждений |
| --- | --- | --- | --- | --- | --- |
| Гибридный | 21 из 24 | 14 из 16 | 5 из 5 | 3 из 3 | 23 из 24 |
| **Гибридный + бренды** | **23 из 24** | **16 из 16** | 5 из 5 | 3 из 3 | 23 из 24 |

Два прогона, результат одинаковый.

**Что нашли evals ответов и что изменено:**

| Что нашли | Почему | Что сделал |
| --- | --- | --- |
| «В энциклопедии нет статьи о Soundcore» — а статья есть | Пользователь написал «саундкор», транслитерация дала «соундкоре», поиск принёс чужие бренды | Нечёткое сравнение с частотной проверкой |
| «Нет статьи о Realme» в «чем отличается Honor от Realme» — а статья есть | Куски Honor заняли все 5 мест | Место в выдаче для каждого бренда из вопроса + список брендов, о которых статьи есть |
| «Ugreen — более премиальный бренд», а во фрагменте сказано «схожее качество» | Модель объединила два утверждения в одно | Поймал судья; на следующих прогонах не повторилось |

Ложный отказ («статьи нет», когда она есть) опаснее выдумки: пользователь уходит с неправильным ответом и не проверяет его. Поэтому evals проверяют оба направления.

**Остаётся:** примерно один ответ из 24 за прогон содержит мелкое обобщение сверх фрагмента («в ряде моделей сочетается с другими технологиями», когда во фрагменте одно конкретное сочетание) — каждый раз в другом вопросе.

## Решения, которые ещё предстоит проверить

- Реранжирование кандидатов (cross-encoder или LLM) — если окажется, что нужный кусок есть в пятёрке, но модель опирается на соседний.
- Модель эмбеддингов крупнее — только если поиск станет узким местом и позволит сервер.
- Судья на другой модели и ручная разметка части ответов — чтобы измерить согласие судьи с человеком.
